## The project in one paragraph

A BepInEx 6 IL2CPP mod for Sea of Stars that turns the game's couch co-op into online co-op by lockstep: every PC runs the full game from the same synced input, the host sends state hashes and guests compare them. When they differ, the guest leaves and drops in again by reloading the host's autosave ("re-sync"). Determinism is the whole game: anything a PC reads that isn't synced input or synced state (clocks, hardware, focus, random, async I/O, UI timing) eventually splits the PCs.

## Testing (two local instances, ~2–3 min per run)

Close the game first; builds deploy into the game folder. `steam_appid.txt` must be in the game folder.

| Command | Use |
|---|---|
| `ENCOUNTER=650 QUIT=5000 bash tests/battle-turns.sh --sosonline-start=0a` | Battle from the user's newest autosave (training grounds); both players take turns over a lagged link. Pass: `guest mismatches 0`, identical turn lines |
| `QUIT=1500 bash tests/save-sync.sh --sosonline-saveat=600` | P1 saves; `SAVER=guest ... --sosonline-saveby=1` for P2. Pass: both PCs show `Saves > a question` then `Saves` again on the same frame, `writes 1/1` |
| `DIVERGE=1600 QUIT=9500 EXTRA="--sosonline-encounter=1500 --sosonline-bot --sosonline-lag=20 --sosonline-jitter=25" bash tests/resync.sh` | Forced re-sync mid-battle; the waiting screen shows and hides, 0 differences after |

Notes:
- Without `--sosonline-lag`/`--sosonline-jitter` most battle bugs don't reproduce: loopback hides real-time dependence.
- The battle splits were intermittent (about half the runs). Run at least 3–4 times before calling something fixed.
- Run hygiene: `tests/display-prefs.sh save`/`restore` around a test session; afterwards delete `SosOnlineTest-*` and `SosOnlineSession-<port>` in `%USERPROFILE%\AppData\LocalLow\Sabotage Studio\Sea of Stars`, never `SosOnlineSession` or `SosOnlineBackup`.
- Scripted save-point interaction doesn't work from the slot-0 start position (the leader isn't in range of the save book); use `--sosonline-saveat`.
- Finding causes: `[combat]`, `[timing]`, `[view]`, `[menu]` lines are logged on both PCs with the lockstep frame. Diff the two logs, and diff the state files by frame (the test state files have no timestamp column: `HASH fN components…`).

## Investigation technique that worked

- Interop assemblies (`BepInEx\interop\*.dll`) can be reflected (copy them to the scratchpad first) to list types and methods. There are no method bodies, so behaviour has to be found by logging.
- `--sosonline-callprobe=TypeA,TypeB` (and `--sosonline-callprobemethods=…`) logs the first call per frame of every method on those types. Diffing two PCs' call sequences finds the first divergent call. It also found the save fix by bisection.
- `NativeCode.IsFolded`: never patch a method that shares native code with others. The audit runs at start (`[fold]` line).
